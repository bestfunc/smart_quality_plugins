## 核心价值主张（3 句话能讲清楚）

### 句 1（功能侧）

> "我们的平台不止有 Web 界面 —— 工程师在终端里一句话，AI 就能跨模块串起来给他答案，不用记界面在哪。"

### 句 2（安全侧）

> "权限不是黑箱：客户每次授权自己勾哪些能力给 AI，所有调用都有审计日志，写操作只开了一个入口而且都生成草稿。"

### 句 3（生态侧）

> "用的是 Anthropic 提出的 MCP 开放协议，客户已经在用的 AI CLI（Claude Code / Codex / Qwen）都能接，不绑特定厂商。"

## 价值主张展开（按客户角色裁剪）

### 对技术决策人（CTO / 技术总监）

强调三点：

- **不锁客户技术栈**：MCP 是开放协议，客户已部署的 AI 客户端能直接接，不强推 Anthropic 全家桶
- **安全可控可审计**：scope 模型 + OAuth 2.1 + 审计日志，符合企业安全治理预期
- **演进可控**：写权限当前只 1 个入口，未来再开"草稿模式"等渐进路径（详见 [reference/08-roadmap.md](../reference/08-roadmap.md)）

### 对一线工程师（数据 / 算法 / QA）

强调三点：

- **不用记界面在哪**：你想做什么，跟 AI 说就行，它自己找页面对应的能力
- **跨页操作压成一句话**：复盘客户报错从"翻 4 个页"变成"AI 给我串起来"
- **不取代 Web**：写操作还是去 Web，AI 只帮你查 + 编排 + 起草

### 对客户的合规 / 安全官

强调三点：

- **细粒度授权**：按模块 × 读写切分的 scope 由用户自己勾，不是 all-or-nothing
- **完整审计**：`mcp_audit_log` 表落每次调用，超管可查
- **物理隔离**：service 层强制按 org + workstation 隔离，AI 拿不到隔壁组织的数据

## 客户常见疑虑应答

### "AI 会幻觉乱编数据吧？"

**核心回答**：AI 调出来的每个值都是后端真实查出来的，不是 AI 自己编的。AI 的"幻觉"只发生在生成自然语言时；调 tool 的返回是结构化 JSON，AI 只是把它呈现给你。

**追加论据**：如果客户仍担心，演示 [scenarios/03](../scenarios/03-sales-demo-workflow.md) 的 Demo 2 末尾"切回 Web 印证 AI 给的数据准确"环节。

### "AI 会不会改坏我们配置？"

**核心回答**：约 20 个 tool 里只有 1 个写，且生成的是草稿要在 Web 人工确认。`detect_flows` 模块完全没开写权限。

**追加论据**：详见 [reference/04-key-concepts.md](../reference/04-key-concepts.md) 的 Scope 段。如果客户问"为啥不开 detect_flows:write"，答案是"产品决策，防 AI 误改生产流程；未来计划走草稿模式渐进开放"（弱措辞，不承诺时间）。

### "我们已经用了 X 客户端（非 Claude），能接吗？"

**核心回答**：MCP 是开放协议。Codex 已验证可用。Qwen 1.0.2 起兼容。其他符合 MCP 规范的 HTTP transport + OAuth 2.1 的客户端理论可接，测试 5 步走 [reference/11-ai-integration.md](../reference/11-ai-integration.md) 末尾。

**话术钩子**：
> "我们设计上就不想绑你们家的 AI 选择 —— 你们用什么我们都能接，今天用 Qwen 明天换 Claude，插件不动。"

### "跟你们 Web 比，强在哪？为啥不直接用 Web？"

**核心回答**：见 [scenarios/03](../scenarios/03-sales-demo-workflow.md) 的 Q1 对比表。一句话：**Web 给"知道点哪"的人，AI 给"知道要什么结果"的人**。互补，不替代。

### "需要培训成本吗？"

**核心回答**：1 行命令装好 + 浏览器一次授权 + 一个 `quickstart` skill 教 AI 能干啥。**新工程师 5 分钟上手**。

**追加论据**：演示 [scenarios/01](../scenarios/01-engineer-onboarding-workflow.md) 的 5 步流程，时长就 5-10 分钟。

### "你们这是免费的吗？怎么收费？"

**核心回答**：插件本身是 Smart TPM 平台**配套交付物**，不单独收费。客户已购平台即获插件能力。

> 如果客户问"那以后会不会涨价" → 弱措辞："当前定位是平台配套，不计划单独定价。"

### "我们能本地部署吗？数据出不出我们机房？"

**核心回答**：MCP server 跑在你们机房的 Smart TPM 后端里（跟 Web 同一个进程）。AI 客户端在工程师本机。**OAuth token + 调用结果都在工程师本机 + 你们机房内闭环**，不经第三方。

**追加论据**：除了 AI 客户端本身可能走云端推理（如 Claude API），插件这一层完全是你们内网的事。

## 演示前现场快速校验（演示前 5 分钟做）

```
□ 投屏字号够大（≥18pt）
□ 终端已 cd 到演示目录
□ 已装 smart-tpm-test 变体（不是 prod！）
□ 浏览器登好了 Smart TPM Web，停在首页
□ 提前 seed 的"客户报错"样本能 100% 复现
□ 网络稳定（OAuth + MCP 调用都吃网）
□ 手机充电，备用流量开着
□ 演示后引导话术（3 行装好命令）准备好
```

## 演示出错的应对

| 情况 | 应对 |
|---|---|
| 网卡了 / OAuth 跳转失败 | "演示环境网络偶尔抖，跟产品本身无关，我们看下一个 demo" → 切到不需要重连的部分 |
| AI 调 tool 返回奇怪结果 | "看，这就是好处 —— 调用过程透明可见，AI 不糊弄你；我们换条数据" |
| AI 选错 skill | "AI 的 skill 匹配有时需要描述更具体，我换种说法" → 用更明确的提示词重来 |
| 出 bug 走不下去 | "今天演示就到这，详细 demo 我们另约时间在你们环境跑" → 不要现场调试 |
