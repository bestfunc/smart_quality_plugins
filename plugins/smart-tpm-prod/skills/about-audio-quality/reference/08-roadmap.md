# 08 · 路线图

> 事实来源：`docs/product_architecture_doc.md` §5.2、git log、README 版本历史。
> **措辞约定**：以下均为*计划 / 在调研 / 设想*，非承诺。状态以最新代码与团队决策为准。

## 定义：当前不支持、列入考虑的方向

| 方向 | 现状 | 规划状态 |
|---|---|---|
| MCP 协议网关 | 标准 MCP 接入层尚未实现，现有 REST 设计已兼容 MCP 封装 | 规划中 |
| 消息队列异步 | 检测为同步响应，未接入 Kafka / RabbitMQ 异步回调 | 待评估 |
| 视频流实时检测 | 仅支持离线音频文件分析 | 待评估 |
| 多语言 SDK | 仅 REST API，无 Java / C# 等 SDK | 待开发 |
| 告警通知（飞书/钉钉/企微 Webhook） | 预留扩展位 | 待对接 |

> 明确**不在范围内**：图像质检（算法层专注音频）、自动模型训练（由 ClearML 独立平台完成，本服务只做推理）。

## 细节：已交付的演进节奏（从 git tag / README 看团队重点）

近期版本主线围绕**集群化 + 可观测性 + DAG 健壮性**：

| 阶段 | 代表性改动 |
|---|---|
| v0.5~v0.9 | 检测引擎成型（v0.5.5）、channel 级参数透传（v0.7.0）、双判定（v0.8.0）、增量复测（v0.9.0） |
| v0.10~v0.12 | API Key 鉴权 + 评分开关 ratingEnabled（v0.10.0）、DB 驱动模型注册（v0.11.0）、API 协议统一 detectId→dataContent JSON + 检测记录全链路追踪（v0.12.0） |
| v0.13.x（近期） | 4 GPU 集群上线（master + 4 worker + nginx）、GPU 全局推理闸门、并发监控、嵌套 fork 死锁修复、全链路异常可追溯、detect_log 三表、disabledRules 覆盖 |

> 团队近期高频在做：并发调优（GPU 闸门、文件锁 race）、可观测性（三表 + 软失败检测）、DAG 节点契约修正。详见 git log 与 `CLAUDE.md` 红线表。
