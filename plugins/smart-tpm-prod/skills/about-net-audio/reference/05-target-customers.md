# 适用场景与目标用户

> 这一份回答"什么场景适合上 net_audio、什么场景不适合"。不写具体客户名（按裁剪边界约束）。

## 一句话

net_audio 适合**算法侧已经清楚自己要分析什么、但缺少持续可靠的多通道音频前端**的工业 / 产线 / 设备类项目。

## 适合的项目特征（满足越多越合适）

### ✅ 业务特征

- **声音是核心信号源之一**：异响、撞击、振动转声波、电机/泵/阀的运行声等
- **事件是瞬时的**：算法需要"刚才那 2-5 秒"的音频，而不是"今天的全量音频"
- **算法侧已经具备**：能做 STFT / 频谱 / DL 模型推理 / 异常检测 / 故障特征提取
- **多麦克风采集需求**：1-4 个麦克风同步采，做空间定位或冗余

### ✅ 工程特征

- **现场有稳定供电 + 局域网**（Wi-Fi 或有线）
- **有算法节点 / PLC / 边缘服务器**承接音频字节并做处理
- **多盒子部署可控**：能给每台盒子规划 IP 段、能在现场跑运维脚本
- **客户接受嵌入式 Linux 的运维门槛**（时钟同步、灵敏度调校、偶尔需要 SSH 上去看日志）

## 不适合的场景

- ❌ **算法尚未确定**：客户还在"用音频能不能做点什么"探索阶段。本产品不送算法。
- ❌ **要做语音识别 / 会议记录**：可以用，但 net_audio 不带 STT；STT 需要客户自己接。
- ❌ **要超低延迟（<10ms）实时分析**：BufferPool 切片返回最快也是几十毫秒，WebSocket stream 也存在网络抖动。算法要求<10ms 闭环不适合。
- ❌ **极端环境（高温/高湿/强电磁）但没有定制硬件**：Rock Pi S + I2S 麦克风板是消费/工业级，不是车规 / 防爆。
- ❌ **零运维要求 / 不接受现场调试**：盒子需要：
  - 时钟校准（无 RTC）
  - 灵敏度按现场实际声场调
  - 偶尔的网络配置
- ❌ **音频要做合规存证 / 长期归档**：RingBuffer 是覆盖式存储，不保证长期保存。需要长期归档要客户在算法节点侧自己存。

## 4 类典型受众画像

> 这是**给 net_audio 输入与输出**的角色，不是终端业务用户。

### A. 算法研发 / 数据科学

- **要的是**：可靠的 4 通道音频字节 + 精确时间戳
- **常做**：调参数（缓冲时长、采样率）、看实时频谱、跑离线模型
- **痛点**：本地复现现场情况，需要拿到现场盒子的历史回放（RingBuffer 提供）

### B. 现场运维工程师

- **要的是**：装上能用、出问题能改、能远程指导现场操作
- **常做**：升级版本、改 IP、调灵敏度、看 journalctl 排故
- **痛点**：多盒子同时上线时区分 / IP 冲突 / 公钥失效（详见 [reference/10-deployment-modes.md](./10-deployment-modes.md)）

### C. 上游算法集成方 / SmartPLC / 业务后台

- **要的是**：稳定的 HTTP/JSON 接口 + 清晰的协议文档
- **常做**：调用 `/api/v1/stop_and_fetch` 取音频、处理 multipart、对接 mDNS 发现
- **痛点**：时间同步必须前置、多通道响应解析、错误码处理

### D. 产品 / 销售（内部）

- **要的是**：跟客户解释清楚"我能干什么、不能干什么"
- **常做**：方案介绍、报价、对接客户技术对话
- **痛点**：客户问"能不能本地推理"、"能不能识别车声"等模糊需求时怎么定边界（**答：不行，算法是客户自己的**）

## "客户在解决什么问题"快速判断框架

跟潜在客户聊的时候，按这个顺序问，能快速判断匹配度：

1. **声音对你们业务的重要性**：是核心信号还是辅助信号？
2. **算法准备度**：已经有可跑通的算法 / 模型，还是只有想法？
3. **现场已有什么**：网络、供电、机柜、有没有可以放盒子的位置？
4. **节奏要求**：每次"取音频"的时延可接受多少？秒级 OK 还是必须毫秒级？
5. **盒子台数**：1-2 个 POC 还是几十台规模化？

匹配度高 → 进 POC；不匹配 → 直接说明边界，不要强凑（强凑后会在交付期被反复扯皮）。

## 部署密度参考

- **POC 阶段**：1-2 台盒子，1 个算法节点对接
- **单产线**：4-8 台盒子（按产线段位 / 关键工位密度），通常 1 个中央算法节点
- **多产线 / 工厂级**：几十台规模，建议加 mDNS 反向代理 / 中央配置下发（**目前路线图阶段**，详见 [reference/08-roadmap.md](./08-roadmap.md)）
