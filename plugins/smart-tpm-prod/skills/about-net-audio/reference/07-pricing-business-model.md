# 商业交付模式

> 这是一份**框架性的内部参考**，具体价格、合同模板、SKU 由商务侧维护。本文件不写具体金额。

## 当前主流交付模式

按出现频率从高到低：

### 1. 硬件 + 软件一体（"盒子整套"）

- 客户买的是**预装好 SmartAudio 的 Rock Pi S 盒子 + 麦克风阵列板**
- 软件版本在出货前固化
- 客户拿到接电源 + 接网线即可
- 出厂前我方负责：刷镜像、配账号、灵敏度初始基线、SN 唯一化
- 客户负责：现场布线、网络规划、对接自己的算法节点

适合：客户的算法/PLC 团队已经准备好，只缺前端

### 2. 软件单独授权（少数）

- 客户自己采购同型号硬件（Rock Pi S 兼容板）
- 我方提供软件包 + 部署文档（类似 release/smartaudio_v3.5.3 目录）
- 通常配合一次集成支持
- 客户负责硬件适配 + 麦克风调试

适合：客户已有硬件供应链 / 想做白标

### 3. OEM 集成

- 客户的产品里嵌入 net_audio 作为子模块
- 通常以 SDK / 库的方式集成，或客户拿源码做改造
- 商务模式通常是 license + 维护

适合：客户做整套设备产品，net_audio 是其中一个子系统

## 商业边界（卖什么 / 不卖什么）

### 卖：
- 音频采集 + 4 通道分发 + 时间窗精准取数能力
- HTTP/WebSocket/mDNS 标准接口
- 现场部署 + 升级 + 排故的工程化方案
- 集成支持（按 POC / 项目计费）

### 不卖：
- 算法 / 模型（这是客户的核心）
- 硬件定制（除非客户付定制硬件费用）
- 长期音频归档存储 / 云端服务
- 终端业务系统 / SCADA / MES

## SKU / 版本分层

当前**未做正式 SKU 分层**。所有客户拿到的功能集合一样，差异在：
- 硬件配置（盒子规格、麦克风型号、外壳）
- 集成支持深度
- 维护期长度

未来路线图里**在调研**做 "Standard / Pro / OEM" 三档分层，但**未承诺时间**。

## 客户成本结构（参考）

> 给销售/客户成功在初次沟通时大致勾勒，具体数额走商务侧 SOP。

- **硬件成本**：盒子 + 麦克风板 + 外壳 + 适配电源 — 主要硬件成本
- **软件许可**：当前按"硬件捆绑"卖，软件本身不单独计价（OEM 模式例外）
- **集成服务**：POC 阶段 / 项目交付阶段按工时
- **维保**：可选，年度 / 多年度

## 销售环节的关键问题（内部 FAQ 触发的源）

跟客户聊到下面这些时，**先看 [faq/](../faq/) 里有没有现成话术**：

| 客户问的 | 看这里 |
|---|---|
| 你们这个能识别什么声音？ | [faq/02-developer-questions.md](../faq/02-developer-questions.md)（"我们不做识别，客户做识别"） |
| 跟某 X 牌录音盒子比有什么优势？ | （本百科**不写竞品对比**，按裁剪边界。需要时商务侧自己拉对比） |
| 一台盒子能管多少个麦？ | 4 个（I2S 阵列板硬件上限），多了用多台盒子 |
| 数据私有化吗？走云吗？ | 全部本地，不上云。算法节点是客户内网的事 |
| 我们的算法不在 Python 上行不行？ | 行。接口是 HTTP/JSON + WAV 字节，跟语言无关 |

## 出厂前商务检查项（销售侧也要看）

> 这是 **(内部参考，不对外发)**。

发货前清单：
- [ ] 灵敏度基线已逐台校（出厂值不要直接用通用 240，按客户现场预期声场调）
- [ ] 时钟同步源已确认（客户网络能不能访问 NTP？走客户内网 NTP 还是公共 NTP？）
- [ ] 静态 IP 段已跟客户对齐（给客户预留改 IP 的接口 `/api/network`）
- [ ] 默认账号密码 + JWT secret 提示客户**首次部署后必须改**（安全债，内部已知风险）
- [ ] 提供运维手册（参考 `release/smartaudio_v3.5.3_20260528/OPS_MANUAL.md`）
- [ ] 提供接入文档（`docs/API_HARDWARE.md` + `docs/API_SENSITIVITY.md`）
