## 现状小结(v3.5)

当前在产形态见 [02-architecture.md](./02-architecture.md):**单台 WPF / .NET 8 桌面应用,装在产线工控机上,承载全部逻辑**——PLC 通信、声学采集、霍尔同步、算法调用、数据库写入、UI 监控,全部跑在同一个进程里,靠 `async/await` + 线程池支撑多工位并发。

这个形态在产线现场稳定运行,但设计稿(§1.1)梳理了几条长期约束,作为演进的出发点:

| 现状约束 | 表现 |
|---|---|
| **多工位共享单进程** | 工位间共享线程池 / GC / MySQL 连接,一个工位的重操作(DB 阻塞、CSV 写)可能拖慢全线 |
| **流程语义硬编码在 C#** | 点位地址、轮询周期、阶段切换条件等"运维语义"写死在代码里,小调整也要走开发→编译→发布 |
| **可观测靠翻日志** | 主要观测手段是 log4net 文件,事故后逆向翻日志,难以实时看到"系统当前在做什么" |

> 这些是演进的*动机*,不是 v3.5 的缺陷判定——v3.5 仍是当前交付与维护的主线。

## 演进方向(v4 / SmartPLCV3,设想)

设计稿提出一个**后台服务化重构**的设想(代号 SmartPLCV3,文档内称 v4)。核心是把"一个大进程"拆成"一组各司其职的小进程 + Web 配置/观测面",目标方向(§1.2)如下:

| 方向 | 设想做法 | 想解决的现状约束 |
|---|---|---|
| **工位微服务化、消除竞争** | 每工位 = 一个独立进程(Windows 服务),物理隔离,互不知道彼此存在,只共享 MySQL(配置+业务)与 Redis(事件+命令) | 多工位共享单进程导致的串扰与跨工位拖累 |
| **PLC 逻辑配置数据驱动** | 点位定义、状态机、转移条件、动作链存进 MySQL 配置表,运维通过 Web 增删改,无需开发改代码重新发布 | 流程语义硬编码 |
| **Python / React Web 配置与监控界面** | Python(FastAPI)后端做配置 CRUD + 工位启停 + Redis↔WebSocket 桥接;React 前端做实时监控页、配置页、日志查询页 | 配置门槛高、缺统一界面 |
| **实时可观测** | 所有 PLC 读写 / DB 调用 / 状态转移 / 异常通过 Redis 广播,Web 端实时看到"系统在哪、在做什么、卡在哪";工件级 correlation_id 串联全链路 | 可观测靠事后翻日志 |

设计稿同时把**迁移安全性**作为设想的硬约束(§10.6):不改 PLC 点位地址、不改现有 MySQL 业务表 schema(只新增配置表)、不要求停产线、任何阶段计划保留 5 分钟内回滚到 v3.5 的能力。迁移设想按单工位试点 → 灰度铺开 → 收尾的阶段推进。

> 上述均为设计稿(Draft 状态)中的设想。是否实施、按何种范围与节奏实施,以实际推进为准。

## 近期进行中 / 在调研的工作主题

这些是 v3.5 主线上**已在进行或在调研**的较小演进,独立于上面的 v4 设想,从 git 近期 commit 主题可见:

| 主题 | 状态 | 依据 |
|---|---|---|
| **新算法引擎对齐** | 进行中 | 已切换到新算法引擎 `/api/v2/detect/execute`(JSON + X-API-Key + stage 级 dataContent),并在做与后端 edge_api 的结果聚合/落库逐项对齐(detect / detect_stage / detect_channel)。详见 [06-integrations.md](./06-integrations.md) |
| **算法 channel 路由健壮性** | 进行中 | 当算法返回的 channel 路由对不齐时,用 point / product 级结果兜底,避免漏判 |
| **MinIO 上传/写库地址解耦** | 在调研 / 已部分落地 | 设想把上传端点与写库端点拆分(Endpoint / PathEndpoint),让现场上传走宿主机可达地址、写库地址给前端可访问 |
| **灵敏度同步增强** | 在调研 | 检测点灵敏度按产品差异化下发给录音盒子的同步链路在做设计(见 [03-key-concepts.md](./03-key-concepts.md) 灵敏度条目),相关设计稿单独存档 |

> "多协议增强"等更广的设想(如更多 PLC 品牌、单 Worker 接多 PLC)在 v4 设计稿的 YAGNI 清单里被列为"暂不做、有需求再加",当前不在计划内。三协议现状见 [04-plc-protocols.md](./04-plc-protocols.md)。

- **时间表以实际为准**:本文不给具体上线日期;任何"何时发布 / 是否包含某能力"的判断,请以当时的实际版本与发版记录为准(见 [10-editions-delivery.md](./10-editions-delivery.md))。
