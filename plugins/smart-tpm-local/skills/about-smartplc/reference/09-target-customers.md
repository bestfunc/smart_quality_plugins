# 09 · 目标客户画像

> 事实来源:系统能力反推(`PlcAdapter/`、`Server/StableWorkflow.cs`、`Server/Algorithm/`、`Server/SmartAudio/`)+ [01-product-overview.md](./01-product-overview.md) 角色表 + `BestPLC/Docs/ProductValidationDesign.md`。
>
> **这是"适用场景画像",不是客户清单**:下面所有行业、规模、角色都是从系统能做什么反推"谁适合用",用通用品类描述,不指向任何真实客户。

## 怎么读这一页

SmartPLC 能不能用在一条产线上,取决于三个硬条件能否同时成立:**有 PLC 自动化、有可被声音区分良劣的工艺、有多工位节拍生产**。本页先把这三条拆开讲适用场景(①),再落到行业(②)、角色(③)、现场前提(④),最后把**不适合**的情况划清楚(⑤),避免误判匹配。

## ① 适用场景定义

判断一条产线是否匹配,看这三条是否**同时满足**:

| 必要条件 | 为什么 | 对应系统能力 |
|---|---|---|
| **产线已有 PLC 自动化** | SmartPLC 是 PLC 与算法之间的"中控",靠读写 PLC 信号驱动检测、回写结果控流转 | 三协议适配层(见 [04-plc-protocols.md](./04-plc-protocols.md)) |
| **产品的良/劣可由声音区分** | 核心检测手段是录音 + 深度学习算法判 OK/NG;若产品无声学特征,无从下手 | 录音盒子采音 + 算法引擎(见 [06-integrations.md](./06-integrations.md)) |
| **多工位、按节拍流转** | 系统按工位并发驱动,信号触发→检测→写回是一个节拍闭环;天然适配流水线 | 每工位一个主流程,产品级子流程(见 [05-detection-workflow.md](./05-detection-workflow.md)) |

补充加分项(有则更顺,无也能上):

- **产品有型号区分**:检测点配置、灵敏度可按产品(productId)差异化下发;系统支持读 PLC 产品编号查库定位产品(`ProductValidationDesign.md`)。
- **同型号大批量**:节拍稳定、复检规则统一,自动化收益最大化。
- **已有 MySQL / 内网环境**:对接成本低(结果落库、配置读取走数据库直连)。

## ② 适用行业画像(通用品类)

凡是"**靠声音判良劣 + 已上 PLC 自动化**"的离散制造场景,都落在适用范围内。下面用**通用品类**描述,不代表任何具体客户:

| 品类方向 | 典型声学质检点 | 匹配度 |
|---|---|---|
| **旋转类零部件**(电机 / 泵 / 风机 / 压缩机) | 异响、轴承杂音、运转噪声、啸叫 | 高 |
| **传动 / 轴承类** | 滚动异响、卡滞、周期性敲击声 | 高 |
| **家电整机 / 部件** | 运转噪音、震动异响、电机声 | 高 |
| **汽车零部件** | 齿轮啮合声、电动部件异响、密封件气密声 | 高 |
| **手持 / 园林 / 动力工具** | 空载 / 负载噪声、机械异响 | 中-高 |
| **阀门 / 气密件** | 泄漏声、气流异常 | 中(依赖工艺能否拾音) |

共同特征:产品在产线上**会运转或被激励发声**,且良品与不良品的声音存在**可被算法学习的差异**。

## ③ 使用角色画像

呼应 [01-product-overview.md](./01-product-overview.md) 的角色表,从"谁在产线上和这套系统打交道"看:

| 角色 | 在客户组织里通常是谁 | 用 SmartPLC 做什么 | 深入看 |
|---|---|---|---|
| **产线运维** | 设备 / 工艺班组 | 配工位、PLC 点位、设备地址、灵敏度,日常维持产线跑 | [scenarios/01-line-operator-setup.md](../scenarios/01-line-operator-setup.md) |
| **质量工程师** | 质量 / QA 部门 | 查 OK/NG 结果、分析缺陷分布、调灵敏度收紧或放宽判定 | [scenarios/02-quality-engineer-review.md](../scenarios/02-quality-engineer-review.md) |
| **现场实施** | 集成商 / 厂商工程师 | 对接客户 PLC、按点位表配点、联调录音盒子 + 算法 | [scenarios/03-field-implementation.md](../scenarios/03-field-implementation.md) |
| **系统管理员** | IT / 设备管理 | 用户认证、日志审计、系统监控与性能诊断 | — |

决策链上还有两类"不直接操作但要被说服"的人:

- **质量 / 生产负责人**:关心次品流出率、产能、人工替代效益(见 [01-product-overview.md](./01-product-overview.md) 核心价值)。
- **IT / 信息化**:关心部署形态(单机现场,见 [08-deployment-config.md](./08-deployment-config.md))、数据落在哪、是否上内网。

## ④ 适配前提(现场要具备什么)

匹配画像之后,真正落地前现场需具备以下条件,否则需先补齐:

| 前提 | 说明 |
|---|---|
| **PLC 及点位可读写** | 客户能提供点位表,且 PLC 协议在 S7-1500 / Modbus TCP / 欧姆龙 FINS TCP 三者之内(见 [04-plc-protocols.md](./04-plc-protocols.md)) |
| **产线工控机(Windows)** | SmartPLC 是 WPF/.NET 8 桌面应用,需一台中控机承载(见 [08-deployment-config.md](./08-deployment-config.md)) |
| **录音硬件(智能设备 / 录音盒子)** | 提供音频采集,一盒多通道,挂在工位下(见 [03-key-concepts.md](./03-key-concepts.md)) |
| **网络可达** | 中控机能连本线 PLC、录音盒子,以及后端 MySQL / MinIO / 算法服务 |
| **算法服务** | 深度学习检测后端可用(端点 `/api/v2/detect/execute`),并已针对该产品的声学特征完成建模 |

> 算法对某产品"听不听得懂"取决于建模质量。**新品类首次接入通常需要采样、训练、调灵敏度的导入期**,这属于落地前的工程量,不是开箱即用。

## ⑤ 不适合的场景

以下情况不在适用画像内,匹配评估时应直接排除或谨慎:

| 不适合的场景 | 原因 |
|---|---|
| **产品无声学特征** | 纯外观 / 尺寸 / 颜色 / 字符缺陷等,声音里没信息,算法无从判定(那是机器视觉的活) |
| **没有 PLC、纯人工产线** | 没有信号可读写,系统的中控驱动模型不成立 |
| **PLC 协议不在三者之内** | 现状适配 S7-1500 / Modbus TCP / 欧姆龙 FINS TCP;其他协议需另行评估适配工作量 |
| **单件 / 单工位手工台** | 系统按多工位节拍并发设计,单点手工场景收益低、不划算 |
| **环境噪声压过产品声** | 拾音信噪比太差,会拉低算法判定可靠性(需先解决声学隔离) |
| **要求云端 / SaaS 化部署** | 现状是产线现场单机部署,无容器化(见 [08-deployment-config.md](./08-deployment-config.md));集中式形态属演进方向,见 [11-roadmap.md](./11-roadmap.md) |

## 一句话匹配判断

> **"已经上了 PLC 的多工位流水线 + 产品良劣能听出来 + 现场能放台 Windows 中控接录音盒子和算法"** —— 三条都点头,就值得往下评估;缺第一条或第二条,基本可以直接排除。
