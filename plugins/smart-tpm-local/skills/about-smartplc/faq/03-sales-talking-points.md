## ① 一句话价值主张

> **"在产线 PLC 和 AI 算法之间放一台 Windows 中控,用声学算法替人耳听检——判定标准统一、全程可追溯、多工位无人值守,按点位表配置就能上线。"**

展开一层(给负责人):**降低次品流出、释放质检人力、检测动作全留痕**。三句话就是核心收益,细节见 [../reference/01-product-overview.md](../reference/01-product-overview.md)「核心价值」。

## ③ 常见异议应对

异议是机会,不是攻击。下面给"客户怎么问 → 我们怎么接",**接的话都不能越过事实层**。

### Q1. "你们准确率多少?"

**别报死数字。** 准确率取决于建模质量与产品声学特征,我们没有一个"对所有产品都成立"的百分比。

> **可以这么说**:"准确率不是一个固定值,它取决于这个产品的声学特征和我们对它的建模质量。**新品类接入通常有一个采样、训练、调灵敏度的导入期**,过了导入期再看稳定表现更有意义。我们可以先用您的产品做小批量验证,用数据说话。"

底气:[09](../reference/09-target-customers.md) 适配前提明确写了"算法对某产品听不听得懂取决于建模质量""新品类首次接入通常需要导入期,不是开箱即用"。**这是诚实卖点,不是短板** —— 把导入期讲在前面,反而比拍胸脯报数字更可信。

### Q2. "这和机器视觉(CCD / AOI)有啥区别?"

**不是替代关系,是互补。** 视觉看得见的(外观、尺寸、字符、颜色)我们不抢;**声学缺陷视觉看不见**——异响、轴承杂音、气密泄漏声、运转噪声这些藏在声音里。

> **可以这么说**:"机器视觉解决的是**看得见**的缺陷;我们解决的是**听得见、看不见**的缺陷——比如电机异响、轴承杂音、密封件泄漏声。很多产品两类缺陷都有,视觉和声学是**两条互补的检测线**,不冲突。"

底气:[09](../reference/09-target-customers.md)「不适合的场景」第一行就写了"纯外观/尺寸/颜色/字符缺陷……那是机器视觉的活";适用行业表里的声学质检点(异响、轴承杂音、泄漏声)都是视觉拿不到的。

### Q3. "上这套,产线改造大不大?"

**改造面比客户担心的小。** 系统是**读现有 PLC 点位**来驱动的,不重做产线控制逻辑;主要现场工作量是配点位、装录音盒子、联调算法。

> **可以这么说**:"我们不改您的产线控制逻辑,是在 PLC 和算法之间加一台中控,**读您 PLC 现有的点位**来驱动检测、回写结果。现场主要是:① 您提供点位表;② 工位上装录音盒子;③ 联调算法。中控机就一台 Windows 工控机。"

底气:[01](../reference/01-product-overview.md) 部署形态(单机中控);[09](../reference/09-target-customers.md) 适配前提(客户提供点位表、装录音硬件、网络可达);[05](../reference/05-detection-workflow.md) 主流程靠读写 PLC 信号驱动,不接管控制逻辑。

> 提醒:别承诺"零改造"。点位对接、声学隔离(信噪比差时)可能有现场工程量,见 [09](../reference/09-target-customers.md)「不适合场景」环境噪声那条。

### Q4. "我们 PLC 是 XX 协议,你们支持吗?"

> **可以这么说**:"现状统一适配西门子 S7-1500、Modbus TCP、欧姆龙 FINS TCP 三种。如果在这三者之内,**开箱适配**;不在的话,需要我们评估一下适配工作量再回复您,**不敢拍胸脯保证**。"

底气:[09](../reference/09-target-customers.md)「不适合场景」明确"PLC 协议不在三者之内……需另行评估适配工作量"。

## ④ 话术红线(踩了就是事故)

| 红线 | 为什么 | 正确做法 |
|---|---|---|
| **不承诺具体准确率数字** | 准确率随建模与产品变化,报死数字交付不了就是违约 | 说"取决于建模 + 有导入期 + 可小批量验证"(见 Q1) |
| **不贬低竞品 / 不踩机器视觉** | 视觉是互补不是对手;贬低显得不专业、还可能撞客户已有投资 | 讲"互补、解决看不见的缺陷"(见 Q2) |
| **不泄露真实客户名** | 事实层全程脱敏,对外提客户是商业失信也违背 skill 红线 | 要案例就说"某类旋转件 / 家电整机产线",用通用品类 |
| **不报营收 / 团队 / 融资 / 内部决策** | 与销售卖点无关,且属裁剪红线 | 聚焦产品能力,这些一律不接 |
| **不承诺路线图时间点** | v4 微服务化等是**演进方向**,没排期承诺 | 用"计划 / 设想 / 路线图"措辞,见 [../reference/11-roadmap.md](../reference/11-roadmap.md) |
| **不夸"零改造 / 即插即用"** | 有点位对接、建模导入期、声学隔离等现场工程量 | 讲"改造面小、读现有点位",但导入期/工程量讲在前面 |

> 一条总原则:**能追到事实层的才往外说,追不到的标 `<TODO>` 问研发**。诚实是这套系统最强的卖点——把导入期、协议边界、改造工程量讲在前面,客户反而更信。
